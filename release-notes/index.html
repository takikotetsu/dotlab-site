メインウィンドウでの取り込みと Sync(同期)にまたがる不具合

  • 取り込み中にカードが抜けて(またはアンマウントされて)ジョブがエラー終了すると、「ほかの作業中は待つ」設定の Sync が、そのあと永久に待ち続けていました。取り込みを再開して完了しても Sync は動かず、アプリを再起動するまで直りませんでした。
    原因は、エラーや停止で終わったジョブが「このドライブを使用中」という印を外さずに終わっていたことです。Sync はその印を見て見送り続けていました。どの終わり方でも印を外すようにしました。
    影響するのは、Sync の「ほかの作業中は待つ」をオンにしていて、同じドライブを使う取り込みがエラーや停止で終わった場合だけです。取り込み自体の結果(コピー済みデータ・照合)には影響ありません
  • エラーや停止で終わったジョブについて、ログに終了の行が残らず、実働時間も記録されていませんでした。あわせて直しています

安全側の作りは変えていません

コピー元は読み取り専用でしか開かない、上書きはしない、.partial 以外は削除しない、メインウィンドウでの取り込みでは必ずコピー先を読み戻して照合する — これらは今回も一切変えていません。

2026-09-13 #

Codex HDE(ARRIRAW の可逆圧縮)に対応しました。あわせて ALEXA 35 のカードが認識されていなかった不具合を直しています。

メインウィンドウでの取り込み: HDE

この節は、メインウィンドウでの取り込みで、Codex の仮想ボリューム(名前の末尾が _hde)をコピー元に選んだときの説明です。物理側のボリュームをコピー元にした場合は、これまでどおり非圧縮の ARRIRAW が取り込まれます。

  • Codex Device Manager で HDE を有効にすると現れる仮想ボリューム(〜_hde)をコピー元にできます。取り込まれるのは HDE で圧縮された MXF です(実測で元の 57〜60%)。ALE などカードの付属ファイルも一緒に入ります
  • この仮想ボリュームは Finder ではコピーできません(Codex の仕様で、ファイルが 0 バイトに見えるため、Finder は空のファイルを作って終わります)。.Lab は届いたデータを最後まで読む作りなので、そのまま取り込めます
  • 取り込み前に表示されるサイズは見込みです。HDE は読み終わるまで大きさが決まらないため、Codex が出す見込み値で表示します。見込みは実際より多めに出ます(実測: 見込み 97.5 GB → 実際 75.7 GB)。空き容量が見込みを下回る場合は、止めずに確認を出します。途中で空きが尽きた場合は、その宛先を止めて書きかけ(.partial)を片付けます。完了したファイルはそのまま残ります
  • 照合は、圧縮後のデータに対して行います。コピー先に書いた圧縮後のファイルを読み戻し、コピー元から受け取ったデータと一致するかを確かめます。カード上の元の ARRIRAW と突き合わせているわけではありません
  • ソース再読(パラノイア)は、この取り込みでは行いません。同じファイルをもう一度読んでも 2 回目はカードに届かない(圧縮結果が OS のキャッシュから返る)ことを実測で確認したため、読み直しても根拠が増えません。設定でパラノイアをオンにしていても、この取り込みでは働きません。ジョブの表示にその旨を出します
  • コピー元の種別は ARRI (HDE) と表示されます。ジョブの記録にも HDE で取り込んだことが残ります
  • 設定に「元 ARRIRAW のハッシュも記録する」が増えていますが、既定はオフで、通常は不要です。後日 HDE から ARRIRAW に戻したものと突き合わせるための材料ですが、その時点でカードは手元に無く、食い違いが分かっても何も回復しません。確かめたい場合は HDE ではなく ARRIRAW のまま保存してください

Sync(同期)と Watch Folder

この節の 1 項目は、Sync と Watch Folder の説明です。

  • Codex の仮想ボリューム(〜_hde)は、Sync と Watch Folder のコピー元にできません。サイズが読み終わるまで決まらないため、「大きさが同じなら変更なし」という差分の判断が成り立たないためです。選ぶとその旨を表示して受け付けません。HDE はメインウィンドウの取り込みで使ってください

カードの認識

  • ALEXA 35 のカードが認識されていなかったのを直しました。クリップ名(例: X_0001C001_…)の区切りをコード側が間違えており、挿しても通知が出ず、種別もリール名も付いていませんでした。HDE 対応より前からの不具合です

外部ツールとの連携

  • status --job <ID> --json の各ファイルに originalHash / originalSize が増えました。上記の設定をオンにした HDE 取り込みでのみ値が入り、それ以外は null です。既存の項目は変えていません
  • コマンドラインの進捗表示が、HDE 取り込みで最後まで 100% にならなかったのを直しました(分母が見込みサイズのままでした)

安全側の作りは変えていません

コピー元は読み取り専用でしか開かない、上書きはしない、.partial 以外は削除しない、メインウィンドウでの取り込みでは必ずコピー先を読み戻して照合する — これらは HDE の取り込みでも同じです。変わるのは上に書いた「照合の相手が圧縮後のデータになる」ことと「ソース再読を行わない」ことの 2 点だけです。

Sync(同期)

この節の1項目は、Sync だけの変更です。

カードの自動認識

  • Sony VENICE・BURANO のカードを認識できるようになりました。これまでは XDROOT というフォルダ名を探していましたが、これらのカードはボリューム名と同じ名前のフォルダを使うため、挿しても通知すら出ずに無視されていました。フォルダ名ではなく中身(Clip フォルダと MEDIAPRO.xml の組み合わせ)で判別するようにしたので、名前が違っても認識します。従来の XDROOT 形式もこれまでどおり認識します
  • カードを挿したままアプリを起動した場合にも、認識するようになりました。これまでは「新しく接続されたドライブ」だけを見ていたため、起動時にすでに挿さっているカードは対象外でした。ただし、起動時に自動でコピーを始めることはしません(「カードを挿す」と「アプリを開く」は別の操作なので、開いただけで始まるのは行き過ぎだと考えました)。コピー元に設定してお知らせするところまでです
  • 認識したカードの表示から、製品ライン名を外しました。同じフォルダ構造を複数の機種が使うため、特定の名前を出すと別の機種で正しくなくなります

メインウィンドウでの取り込み

  • 取り込みの実行中にプロジェクト名を変更すると、そのジョブだけが古い名前のプロジェクトに分かれてしまう問題を直しました。実行中のジョブが、後半の処理(チェーンコピーやフォルダ監視の差分)でプロジェクトを名前で引き直していたため、名前を変えた後に古い名前のプロジェクトが作り直されていました
  • リールの書き出しに、サイドバーからも辿り着けるようにしました。サイドバーのリールを右クリックすると、リールを開く・ASC MHL の書き出し・レポートPDF の書き出しが選べます。1.4.1 で完了リールの一覧を畳んだため、そこからしか辿れない状態になっていました

追加した機能

  • リールを別のプロジェクトへ移せるようになりました。サイドバーのリールを右クリック →「プロジェクトへ移動」。変わるのは記録上の所属だけで、コピー先のファイルは元の場所から動きません。移動先に同じ名前の Bin が無い場合、その分類からは外れます
  • コピー先を記憶し、アプリを再起動しても復元するようになりました。プロジェクトごとに覚えるので、プロジェクトを切り替えると、そのプロジェクトのコピー先に入れ替わります。
    前回と同じドライブだと確認できたときだけ復元します。同じ名前で別のドライブが接続されている場合は、空欄のままにします(/Volumes/SSD_A が今日も同じディスクとは限らないためです)。ドライブが接続されていない場合も空欄になります

安全側の作りは変えていません

コピー元は読み取り専用でしか開かない、上書きはしない、メインウィンドウでの取り込みでは必ず読み戻して照合する — これらは今回も一切変えていません。

Sync(同期)

この節の3項目は、Sync だけの変更です。

  • コピーに失敗したペアが、そこで止まってしまう問題を直しました。これまでは初回コピーで1件でも失敗すると監視に入らず、そのペアは以後まったく同期しませんでした。画面上は「同期が終わっていないのにコピーが始まらない」状態になり、.Lab を再起動するまで戻りませんでした。いまは失敗しても監視を続け、失敗したファイルを次の巡回で再試行します。成功したようには表示せず、「◯件がコピーできませんでした。次の巡回で再試行します」と件数を出します
  • 「ほかの作業中は待つ」が、初回コピーでは効いていませんでした。この設定は巡回にしか入っておらず、Sync は起動のたびに初回コピーから始まるため、実際には一度も待っていませんでした。同じドライブへ取り込みが書いている最中に Sync が読みに行き、コピーの失敗を招いていました。いまは初回コピーも、取り込みが終わるまで待ちます
  • すでにコピー済みかどうかの判定に、コピー先のファイルサイズを加えました。これまではコピー先にファイルが「ある」ことだけを見ていました。名前は中身を保証しないため、判断の根拠としては足りていませんでした

コピー元の読み取りが遅いときの扱い

  • 「メディアが物理的に抜かれた可能性」と決めつけないようにしました。これまでは読み取りが15秒返らないだけで、抜かれたものとして停止していました。実際には接続されたままで、別の作業と重なって混んでいただけ、という事例が出ました。いまはドライブが見えているかどうかを確かめてから、どちらであるかを書きます
  • 読み取りの待ち時間を15秒から90秒に延ばしました。この時間は「応答が永久に返らない状態」を見分けるためのもので、遅いドライブを打ち切るためのものではありません。外付けドライブから大きなファイルを読んでいるときに、15秒では足りない場合がありました

メインウィンドウでの取り込み

  • カードを挿した時点で、取り込み済みの可能性をお知らせします。同じプロジェクト内に、ファイル数と合計サイズが完全に一致する取り込み済みのリールがある場合、コピー元の欄に注意を表示します。止めることはしません(再取り込みが必要な場面もあるため)。これまでは「オフロード開始」を押すまで気づけませんでした

安全側の作りは変えていません

コピー元は読み取り専用でしか開かない、上書きはしない、.partial 以外は削除しない、メインウィンドウでの取り込みでは必ず読み戻して照合する — これらは今回も一切変えていません。

  • 画面を「入力」「進行中」「完了」の3つに分けました。これまで入力欄と進捗が同じ見た目だったため、リール名の欄が2つ並んでいるように見えていました。入力は左に紫の線が入った帯、進捗は1枚のカードになります

.Lab 1.4.0

2026-08-13 #

Sync(同期)を追加しました。作業中のプロジェクトを、もう1台のドライブへ複製し続ける機能です(Pro)。

Sync でできること(以下はすべて Sync の説明です)

  • 変更を自動で検知します: OSからの通知を受け取り、書き込みが止まって10秒後に同期します。フォルダ全体を数え直し続ける必要がないので、負荷はほとんどありません
  • 2回目以降は一瞬で始まります: 確認済みのファイルを記録しているので、変わっていないものは読まずに飛ばします
  • 組み合わせは何組でも: 社内SSD_A → 社外SSD_A、社内SSD_B → 社外SSD_B のような複数のペアを、1枚のウィンドウで見られます
  • ベリファイは選べます: 既定はオフ(サイズと更新日時で判断)。入れると、コピーしたファイルを読み直してハッシュ照合します。オフのときも、コピーしたファイルのサイズは必ず確認します
  • 元から消えたファイルの扱いも選べます: コピー先に残すか、一緒に消すか。消す設定のときは、開始する前にそう表示します
  • 勝手には始まりません: ウィンドウを開いても、開始は必ずご自身で押していただきます

Sync は作業中のデータのバックアップ用です。カードからの取り込み(オフロード)は、これまでどおりメインウィンドウで行ってください。メインウィンドウでの取り込みにはリール名・レポート・MHL・重複検出があり、ベリファイも必ず行われます。Sync にはこれらはありません。

そのほかの改善

  • ベリファイを切れる場所でも、書けたサイズを必ず確認するようになりました。合わなければ書きかけを破棄し、正式な名前は付けずに報告します。ベリファイを切れるのはチェーンコピーとSyncの2か所だけで、カードからの取り込みでは必ずベリファイが行われます(切る設定はありません)
  • 書き込み途中のファイルを掴んだ場合の扱いを整理しました。取り込みではこれまでどおりエラー、同期では次の巡回に回します
  • 検証用ビルドが公開版と違うバージョンを名乗るようにしました。サポートのご連絡をいただいたときの取り違えを防ぐためです
