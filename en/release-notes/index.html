.Lab 1.5.11

2026-11-27 #

A readability release. Dimmed text is brighter, and reel names that were being cut off now fit.

Text contrast

  • Dimmed text (small labels and secondary figures) is brighter. It was too dim for text that small. This applies to the main window, Sync and the Compare window

Reel names that were cut off

All of the following apply when the reel name contains folder levels, such as CARNEM/DIA_04/S006.

  • In the main window's In progress list, the reel name was cut off. The column is wider, and when a name still does not fit, the beginning is dropped so the reel name at the end stays readable. Hover the row for the full path
  • Job History had the same problem: the column was too narrow, so any name with folder levels was always shortened. It is wider now. The project name shows in full on hover as well
  • The heading of the selected job wrapped onto two lines when the window was narrow. It is kept to one line

Card size

  • The total size of the card being offloaded is now clearly readable. It is the figure that tells you how long the job will take, and at the same weight as the clip count it was easy to miss. This covers both "7 clips / 9.3 GB" under Source and "Copied … / …" during the copy, in the main window

.Lab 1.5.10

2026-11-26 #

Sync gets a Compare window. This release also fixes the report, adds missing help chapters, and makes a few things easier to read.

Compare window (new)

  • Source and destination side by side. Open it from the Compare button on a Sync pair. It replaces lining up two Finder info windows
  • It compares sizes only. It does not look at content. You get item counts, totals and folder counts, plus the names of files missing at the destination, files whose size differs, and files only at the destination
  • It only reads. Nothing is written
  • It keeps counting while the window is open. It waits as long as the last pass took, so large folders are checked less often. The Auto checkbox in the footer stops it
  • The lists of differences start collapsed. Click a heading to open one

Display

  • The zero no longer has a slash through it. At small sizes, and in dimmed text, it was hard to tell from an 8
  • The REELS sidebar now shows only the last part of the reel name. With folder levels in the name, the part that matters was cut off even at full width. Hover a row for the full path. The job list, reports, logs and MHL keep the full path as before
  • In Job History, a reel name with folder levels wrapped onto three lines and broke the row height. It is kept to one line now, shortened in the middle so the end stays visible. Hover for the full path

PDF report

  • The playback-check notice is now printed in the report's language only. 1.5.9 printed both Japanese and English, so Japanese was still on the page in an English report. Printing a language the reader cannot read serves no purpose, so only one is printed now
  • Fixed the notice breaking mid-sentence. "(e.g. " was being treated as the end of a sentence

Help

  • Added chapters for Chain copy and Sync. Neither had a single line of documentation
  • The English help had no "Exports and records" chapter (PDF report, MHL, bins). It is there now

.Lab 1.5.8

2026-11-04 #

Two Sync fixes.

Sync

  • Files that already existed at the destination were recorded as "verified" without being checked against the source. Sync used the record plus the file's presence to decide, and skipped it from then on. A name does not guarantee the contents, so that was not a basis for saying a file was done. The size at the destination is now compared against the source before anything is marked verified
  • "First copy complete" was shown even when files had failed. It now states how many could not be copied and that they will be retried on the next pass

.Lab 1.5.6

2026-10-28 #

The reel name field has been rebuilt, and Sync no longer stalls silently.

Offloading in the main window: the reel name

  • The reel name is now a row of slots. Instead of typing Day01/ALEXA35/A001 into one field, you get separate boxes side by side. Separators can no longer be typed — the point is that you can see where the levels break
  • You can add a slot anywhere between the existing ones. Each separator position is itself the add button. Adding only at the end would make it impossible to insert a level before something you already typed
  • The leading slots offer the names you have already used on this project. They come from the record of copies actually made, not from anything .Lab invents. A name you have never used does not appear — so when the day rolls over to Day02 you have to type it, and that is exactly where you notice. Suggestions are listed newest first, with the date each was last used
  • Applying the reel name read from the card no longer wipes the slots before it. It used to replace the whole field, so Day01/ALEXA35/A001 became just A002 and the copy landed directly at the root of the destination
  • ASC MHL is now written even when the reel name contains levels. And a reel name that would point outside the destination stops the job before it starts

Sync

  • A stalled destination is no longer hidden. 87 files that would not fit on a full drive were shown as "no differences"
  • If it stopped because of space, it now says so by name.
  • A pass without enough free space writes nothing and is skipped, instead of writing part of the way and failing

Elsewhere

  • Completed jobs show a breakdown of their contents. With more than one destination, the breakdown is carried on the total as well
  • Clicking a project name shows the breakdown for the whole project.
  • Fixed ALEXA ProRes cards (.mov) not being detected automatically.

.Lab 1.5.1

2026-09-15 #

Fixes Sync getting stuck. Nothing else.

A fault spanning offloading and Sync

  • If a card was removed (or unmounted) mid-offload and the job ended in an error, a Sync pair set to "wait while other work is running" waited forever afterwards. Resuming and completing the offload didn't help; only restarting .Lab did.
    The cause: a job that ended in an error or was stopped never cleared its "this drive is in use" mark. Sync kept seeing the mark and standing aside. The mark is now cleared however the job ends.
    This only affected you if Sync's "wait while other work is running" was on and an offload using the same drive ended in an error or was stopped. Offload results — copied data and verification — were never affected
  • Jobs that ended in an error or were stopped left no closing line in the log and no recorded working time. Fixed at the same time

The safe-side rules are unchanged

The source is only ever opened read-only, nothing is overwritten, nothing but .partial is deleted, and offloading in the main window always reads the destination back and verifies — none of this has changed.

.Lab 1.5.0

2026-09-13 #

Adds support for Codex HDE (lossless compressed ARRIRAW), and fixes ALEXA 35 cards not being detected.

Offloading in the main window: HDE

This section describes offloading in the main window with a Codex virtual volume (name ending in _hde) as the source. Choosing the physical volume instead still gives you uncompressed ARRIRAW, as before.

  • The virtual volume that appears when HDE is enabled in Codex Device Manager (…_hde) can be used as a source. What you get is HDE-compressed MXF (measured at 57–60% of the original), together with the card's companion files such as ALE
  • That virtual volume cannot be copied in the Finder. By Codex's design the files appear to be 0 bytes, so the Finder creates empty files and stops. .Lab reads until the data ends, so it offloads correctly
  • The size shown before offloading is an estimate. HDE's size is not settled until the read finishes, so Codex's estimate is displayed. It runs high (measured: 97.5 GB estimated → 75.7 GB actual). If the free space is below the estimate you are asked to confirm rather than stopped. If space does run out, that destination is stopped and its .partial files are cleaned up; completed files stay
  • Verification is against the compressed data. The compressed file written to the destination is read back and compared with what was received from the source. It is not compared against the original ARRIRAW on the card
  • Source re-read (paranoid mode) does not run for these offloads. Reading the same file twice was measured never to reach the card a second time — the compressed result comes back from the OS cache — so a re-read adds no evidence. Even with paranoid mode on in settings it does not run here, and the job says so
  • The source type is shown as ARRI (HDE), and the job record notes that it was offloaded via HDE
  • Settings gain "also record the original ARRIRAW hash", but it is off by default and normally unnecessary. It exists to compare against ARRIRAW restored from HDE later, but by then the card is gone, so a mismatch recovers nothing. If you want that certainty, keep the ARRIRAW rather than HDE

Sync and Watch Folder

The item in this section describes Sync and Watch Folder.

  • A Codex virtual volume (…_hde) cannot be used as a source for Sync or Watch Folder. Its size is not settled until the read finishes, so "same size means unchanged" — the basis of the difference check — does not hold. Selecting one is refused with that explanation. Use HDE for offloading in the main window

Card detection

  • Fixed ALEXA 35 cards not being detected. The clip name separator (e.g. X_0001C001_…) was parsed wrongly, so inserting a card produced no notification, no type and no reel name. This predates HDE support

Working with other tools

  • status --job <ID> --json gains originalHash / originalSize per file. They are filled in only for HDE offloads with the setting above turned on, and null otherwise. Existing fields are unchanged
  • Fixed the command line progress never reaching 100% on HDE offloads (the denominator stayed at the estimated size)

The safe-side rules are unchanged

The source is only ever opened read-only, nothing is overwritten, nothing but .partial is deleted, and offloading in the main window always reads the destination back and verifies — all of this holds for HDE too. The only differences are the two stated above: verification is against the compressed data, and the source is not re-read.

.Lab 1.4.3

2026-09-08 #

Mostly fixes, found on real shoots, plus two new features.

Sync

The item in this section is Sync only.

  • Half-written files left at the destination were never cleaned up. An interrupted copy can leave a .partial file behind. These were excluded both from deletion and from the difference count, so the screen said "no differences" while they sat there permanently — 223 MB of leftovers was reported in the field.
    They are now cleaned up even when "make an exact match" is off, because a .partial is not your footage, it is .Lab's own temporary file. Files currently being written are not touched (only ones untouched for five minutes qualify). Anything cleaned up is written to the log

Card detection

  • Sony VENICE and BURANO cards are now detected. .Lab looked for a folder named XDROOT, but these cards use a folder named after the volume, so inserting one produced no notification at all. Detection now looks at the contents (a Clip folder together with MEDIAPRO.xml) rather than the folder name, so the name no longer matters. The older XDROOT layout is still detected
  • A card already inserted when the app launches is now detected too. .Lab only watched for newly connected drives, so anything already mounted was ignored. It will not start copying on launch — inserting a card and opening an app are two different actions, and starting on the second one goes too far. It sets the source and tells you
  • Product line names were removed from the detection message. Several models share one folder layout, so naming one model makes the message wrong on another

Offloading in the main window

  • Fixed a running job splitting off into a project under the old name when you rename the project mid-offload. The later stages (chained copies, watch-folder differences) looked the project up by name, which recreated the old one after the rename
  • Reel exports are reachable from the sidebar. Right-click a reel for open, export ASC MHL, and export the PDF report. 1.4.1 folded away the completed-reel list, which was the only route to them

New features

  • Reels can be moved to another project. Right-click a reel in the sidebar → Move to project. Only the record changes; the copied files stay exactly where they are. If the destination project has no bin of the same name, the reel leaves that classification
  • Destinations are remembered and restored across restarts. They are stored per project, so switching projects switches the destination with it.
    A destination is only restored when .Lab can confirm it is the same drive as last time. If a different drive with the same name is connected, the field is left empty — /Volumes/SSD_A is not necessarily the same disk today. It is also left empty if the drive isn't connected

The safe-side rules are unchanged

The source is only ever opened read-only, nothing is overwritten, and offloading in the main window always reads back and verifies — none of this has changed.

.Lab 1.4.2

2026-08-27 #

Sync fixes, all of them found on real shoots. Nothing here changes offloading in the main window.

Sync

The three items in this section are Sync only.

  • Fixed a pair stopping dead after a failed copy. If even one file failed during the first copy, the pair never entered its watch loop and never synced again. On screen it looked like "the sync hasn't finished but no copying is happening", and only restarting .Lab brought it back. It now keeps watching after a failure and retries the failed files on the next pass. It does not pretend to have succeeded: it states how many files could not be copied and that they will be retried
  • "Wait while other work is running" was not applied to the first copy. The setting only existed in the watch loop, and Sync starts with a first copy every time it launches — so in practice it never waited. Sync would read from a drive an offload was writing to, and cause copy failures. The first copy now waits as well
  • Deciding a file is already copied now includes the size at the destination. It used to check only that a file was there. A name does not guarantee the contents, so that was not enough to go on

When the source is slow to read

  • No longer assumes the media was physically pulled. A read that didn't return within 15 seconds was treated as a removed card and stopped the job. In practice the drive was still connected and simply busy with other work. .Lab now checks whether the drive is still visible before deciding which of the two it is
  • The read timeout is now 90 seconds, up from 15. This timeout exists to recognise a read that will never return, not to give up on a slow drive. Reading a large file from an external drive could take longer than 15 seconds

Offloading in the main window

  • You are told when a card may already have been offloaded. If a reel in the same project matches the card exactly in file count and total size, a notice appears on the source field. It does not stop you — re-offloading is sometimes exactly what you want. Until now this was only apparent after pressing Offload

The safe-side rules are unchanged

The source is only ever opened read-only, nothing is overwritten, nothing but .partial is deleted, and offloading in the main window always reads back and verifies — none of this has changed.

.Lab 1.4.1

2026-08-16 #

Screen layout, and fixes where the display disagreed with the facts. No new features.

Offloading in the main window

  • The hash used for verification is now shown per file. Under the "xxHash64" heading there used to be only a progress bar; now the actual values (e.g. 8d7b5326a1f0c942) are listed, turning green once verified. They can be selected and copied, so you can paste them into another tool and compare
  • The window is split into Input, Running and Done. Input fields and progress looked alike, so the reel field appeared to be there twice. Input is now a band with a purple rule on the left; progress is a card
  • The input fields fold to a single line while copying, and keep showing which folder the next offload goes to. Cards can still be dropped on the folded form
  • A running job that appeared twice on screen now appears once
  • Elapsed time is now the time actually spent. It used to be end minus start, so a job paused overnight read "27 hours". Paused time is excluded. Jobs completed before this version are unchanged (the working time wasn't recorded)

Sync

The three items in this section are Sync only. Offloading in the main window is unaffected.

  • Files still being written (.partial) are no longer copied. Sync used to grab them and fail, every pass
  • Added the "while other work is running" setting. Choose whether Sync stands aside while an offload is using the same drive. The default is to wait. Competing for one drive slows the offload visibly (measured: 275 MB/s → 164 MB/s), so waiting is the default
  • Sync jobs no longer appear in the job history. Sync is work that never finishes, so every stop was listed as "interrupted" and buried the real offload failures. The records are still kept and can be followed from the support information

Working with other tools

  • A command line tool now ships inside the app, at /Applications/dotLab.app/Contents/MacOS/offload-cli
  • Add --json for machine-readable output. list --json gives the job list; status --job <ID> --json gives one job in detail (each file's relative path, size, xxHash64, per-destination state and failure reason). The output carries a schema number, and we will not change its shape quietly
  • If all you need is hashes, ASC MHL v2 is still written to the ascmhl folder at the destination, as before

Demo mode

  • Fixed the speed limit not working. When the app was renamed from Offloader to dotLab, the check for demo mode kept looking for the old name, so neither the limit nor the virtual drive allocation did anything
  • Copy speed (10 / 40 / 120 MB/s) and clip count (18 / 60 / 150) can be chosen, with an estimate per clip
  • Fixed demo data being deleted while still in use. A queued job's source could disappear, so the moment its turn came it failed with "no files to copy". Data something still points at is now left alone
  • Settings show how much space the demo area uses, with a delete button. Demo destinations are not removed automatically

The safe-side rules are unchanged

The source is only ever opened read-only, nothing is overwritten, nothing but .partial is deleted, and offloading in the main window always reads back and verifies — none of this has changed.

.Lab 1.4.0

2026-08-13 #

Adds Sync — keeps a second drive continuously mirrored with the project you are working on (Pro).

What Sync does

Everything in this section describes Sync only.

  • Detects changes by itself: it listens to the system and syncs 10 seconds after writing stops. Nothing has to re-count the folder over and over, so the load is negligible
  • Later passes start instantly: verified files are recorded, so anything unchanged is skipped without being read
  • As many pairs as you like: internal SSD_A → external SSD_A, internal SSD_B → external SSD_B, all visible in one window
  • Verification is optional here: off by default (size and modification date decide). Turn it on and copied files are read back and hash-checked. Even with it off, the size of every copied file is always checked
  • You choose what happens to files deleted at the source: keep them at the destination, or delete them too. If deletion is selected, it is stated before the pair starts
  • It never starts on its own: opening the window does nothing. You press start

Sync is for backing up work in progress. Offloading from cards stays in the main window. Offloading in the main window has reel names, reports, MHL and duplicate detection, and is always verified. Sync has none of those.

Other improvements

  • Where verification can be turned off, the written size is now always checked. If it doesn't match, the partial file is discarded and reported, and never given its final name. Verification can only be turned off in chained copies and Sync; offloading from a card is always verified (there is no setting for it)
  • Files that are still being written when .Lab reaches them are handled more clearly: an error during offload, as before; deferred to the next pass during Sync
  • Test builds now report a different version number from the public release, so support reports can't be confused between the two
